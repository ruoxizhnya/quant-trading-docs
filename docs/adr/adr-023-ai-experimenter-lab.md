## Context

ADR-022 定义了"单一数据面 + 两个对等工作面 + 飞轮闭环"。方向部分正确（单一数据面、内容坐标证据应保留），但存在三个结构性问题：

1. **两个对等工作面导致两套编排**。EquityDeep 必须自证是一个"工作面"，于是需要独立的 L2 编排与 L3 体验；两套东西要"对等"，就必须互相解释关系——**飞轮是为补这个窟窿而发明的**。用户反馈："我不清楚它在整个工具中的位置，只是硬性地把它加了进去。"

2. **编排权分散**。ADR-022 里 AI（Hermes）与 EquityDeep 的研究流水线是两个智能流程，用户需要同时监督两个会出错的东西。

3. **定位错位**。用户真实的第一性原理不是"横截面 + 纵向"的对偶，而是：**"AI 不需要 UI，而没有 UI 我又不知道 AI 在做什么"**——即 **AI 的可监督性**。ADR-022 通篇未触及这一点。

同时明确了一条用户约束：**这是单人自托管工具**，多租户 / RBAC / 计费 / 高可用均为纯负担。

## Decision

### 1. 顶层定位：一个实验室，三个角色

| 角色 | 谁 | 职责 |
|---|---|---|
| **实验室主任** | 人（用户） | 给方向、批阅、拍板。不操作仪器 |
| **AI 实验员** | Hermes agent | **操作底座**：挖因子、调系数、跑回测、看结果、决定下一步 |
| **验证器**（validation subagent） | 验证方 | **主动证伪**，被调用、不自主循环；输出概率估计 + 质疑清单 |

**AI 是操作员，不是生成器。** 底座是仪器，已存在且可用；缺的是"操作它的人"和"看见他在干什么的窗"。

### 2. 三层模型，编排者唯一

```
L3  AI 编排层    AI 实验员（唯一编排者，会循环） · 因果审查（被调用，不循环）   ← 唯一需要人在环
L2  能力层       [MCP Tool Bridge] → 因子计算 | 回测 | 产业链查询 | 证据查询 | 验证器链×5   ← 禁止 AI 直接摸数据
L1  数据层       行情 | 财务 | 产业链图谱 | 研究洞察 | 实验日志
```

- **分界线是"能否无人值守"**，不是"静态 vs 动态"。L1/L2 给定输入必有确定输出，可自动测试；L3 会失败，必须可监督。
- **能力层存在的意义是拦住 AI 直接读库/读文件**。现状已有违反（`pkg/tools/builtin/research_tool.go:364` 直接 `os.ReadFile` 读 vault），须收敛。
- **编排者只有一个**。禁止 EquityDeep 成为第二个 agent。

### 3. EquityDeep 从"工作面"降为"数据底座"，拆成两块

| 块 | 性质 | 去向 | 能否当因子 |
|---|---|---|---|
| **① 产业链图谱** | 公司-环节归属、上下游映射、传导指标 | L1 数据层，与行情/财务并列 | **能** |
| **② 研究洞察** | "为什么值得关注"的自然语言 | L1，供 AI 生成假设时检索 | 不能 |

- 纵向深度研究从"**研究的前置步骤**"变为"**被异常触发的按需动作**"。不再要求验证一个想法前先给几十家公司各写完整档案。
- 产业链数据最有价值的形态是**传导信号**（上游涨价 → 下游毛利受压），而非行业标签。
- 每个因子增加 `hypothesis_source` 字段：**从产业链假设出发挖出的因子天然带因果解释**，这解决"AI 挖的因子不敢用"问题。
- 保留"7-stage 流程"中属于**确定性抽取**的部分；涉及 LLM 的部分并入 Hermes 作为技能。

### 4. 挖掘 agent + 被调用的验证器（validation subagent）

**编排者只有挖掘 agent（Hermes）一个**——它会循环、会决定下一步。

**红队不是第二个编排者，是被调用的验证器（invoked validator / validation subagent）**：
不自主循环；输入一份提案 → 运行一次 → 输出质疑清单与概率 → 结束。

#### 验证器拆解：5 个确定性校验器 + 1 个因果审查

| 维度 | 性质 | 归属 | 内容 |
|---|---|---|---|
| 统计 | 确定性 | **L2** | 多重检验校正（试了 N 次，门槛就按 N 收紧） |
| 经济 | 确定性 | **L2** | 扣除手续费、滑点、冲击成本后的净收益 |
| 稳健 | 确定性 | **L2** | 参数敏感度、分年度、分市值/行业 |
| 偏差 | 确定性 | **L2** | 前视偏差、幸存者偏差、复权口径 |
| 冗余 | 确定性 | **L2** | 与已有策略的相关性（防"伪分散"） |
| **因果** | 需语义理解 | **L3** | 讲得出它为什么有效吗 |

> **关键结论：六个维度里五个是纯计算，不需要 LLM。**
> 因此验证器的实现成本与不确定性都比"再做一个 agent"低一个量级——**只有"因果"一项真正需要语言模型**。

#### 信息隔离

| | 挖掘 agent | 验证器 |
|---|---|---|
| 能看到 | 训练期数据 + 全部工具 | **保留期数据** + 提案 + **完整实验日志** |
| 看不到 | 保留期数据（防偷看） | 挖掘 agent 的推理过程（防锚定） |
| 输出 | 候选 + 因果来源 | **概率估计 + 质疑清单**（不是通过/不通过） |

验证器必须看到实验日志：**试 5 次撞出来的和试 500 次撞出来的，同样结果，可信度差一个量级。**

- 验证器**不是复现者**。用同一把尺子量第二次不增加置信度。
- **拒绝多 agent 投票与 arbitrator 仲裁**：错误相关会放大偏差；仲裁层不可解释，违背可监督性。

### 5. 目标是可校准，不是准确

系统输出"未来有效的概率 X%"，考核指标为**校准误差**（声称 60% 的应实际命中 50–70%），而非推荐准确率。
理由：校准良好的信心才能用于配仓位；不准却表现得有把握会导致重仓受伤。

### 6. 核心部件按实盘-ready 设计（2026-10-08 补充，D1）

本 ADR 的「不上实盘、只验证逻辑」前提**不推翻**。但模块化内核改造（见 [design/kernel/target-architecture-modular-kernel.md](../design/kernel/target-architecture-modular-kernel.md)）引入一条补充原则：

**核心部件的抽象（`Broker` / `DataFeed` / `Clock` / `ExecEngine` / `Reconciliation`）本着将来做实盘去设计、留足冗余**——接口形状按真实券商设计（支持部分成交、撤单、订单状态机、断线重连语义），但当前只实现 paper / 模拟撮合。**实盘专属部件（真实券商 SDK 对接、FIX 协议、合规报送）不做，留作将来。**

理由：回测-实盘同构（同一份策略代码，回测换 VirtualClock + PG 快照、实盘换 LiveClock + 推送 feed）只有核心抽象实盘-ready 才成立；paper trading 是同构验证手段，不是真实下单。这条把「实盘能力」从「被排除」改为「预留冗余但不启用」，防止未来接实盘时要推翻核心抽象重写。

## Consequences

### 正面

- 编排者从 2 个收敛到 1 个，消除一整层复杂度
- EquityDeep 有了明确位置（数据层）与明确调用者（Hermes）
- 可监督性成为一等需求，直接对应 UI 的核心形态（异步审阅台，而非操作台）
- 保留 ADR-022 中正确的部分：单一数据面、内容坐标证据、按数据性质分区

### 负面 / 代价

| 代价 | 缓解 |
|---|---|
| 需新建实验日志与循环控制器（现无） | 列为 P1-1 / P1-2；可先用现有 TPE/遗传算法当"假实验员"跑通回路 |
| EquityDeep 的"研究档案"形态弱化 | 档案仍可产出，但不再是前置步骤，而是按需 |
| ADR-022 的既有引用失效 | 已批量修复链接，旧 ADR 保留在 `archive/superseded-adr/` |

### 风险

| 风险 | 等级 | 应对 |
|---|---|---|
| **前视偏差未修**（`fundamentals.go` trade_date=end_date），所有回测数字不可信 | **高** | P0-1，先于本 ADR 的一切建设工作 |
| 飞轮假设（结论能转化为有 alpha 的因子）从未验证 | **高** | 先人工跑通 1 圈验证假设，再投入建设 |
| AI 挖掘产生大量假阳性 | 中 | 实验日志天然记录"试了多少次"，过拟合检测是其免费副产品 |

## Alternatives Considered

| 方案 | 为何不选 |
|---|---|
| **维持 ADR-022（双工作面 + 飞轮）** | 两套编排、EquityDeep 位置不明、未触及可监督性 |
| **完全合并为单仓单体，EquityDeep 用 Go 重写** | 摧毁 Python 生态与产业链分析能力，成本 >> 收益 |
| **多 agent 投票 / arbitrator 仲裁** | 错误相关放大偏差；仲裁层不可解释，违背核心目标 |
| **本方案** | —（采纳） |
