**版本**: v1.1（可实现版，按 ADR-022 修订）
**状态**: 开发依据
**交付物**: 一个 Python CLI + 一个 Obsidian Vault + 一个 `equitydeep-research` worker 容器（共享平台 PostgreSQL）
**范围**: A股个股深度研究 Agent MVP

> 本规格中"工作面 1""研究档案为首要产出"等表述均已过时，**阅读时请以此 banner 为准**；三个硬承诺与逐数溯源仍然有效。

**归属**（历史表述，已被上方 banner 取代）: EquityDeep 是本产品的**工作面 1（纵向深研）** —— 顶层定位见 [PRODUCT.md](../../PRODUCT.md)；架构决策见 [ADR-022](../../archive/superseded-adr/adr-022-unified-research-platform.md)（取代 [ADR-021](../../archive/superseded-adr/adr-021-equitydeep-research-layer.md)）；整合方案见 [archive/RESEARCH-equitydeep-legacy.md](../../archive/RESEARCH-equitydeep-legacy.md)；本规格的待改进项见 [ODR-047](../../archive/odr/odr-047-equitydeep-integration-audit.md)

>
> | 项 | v1.0（本文档原假设） | v1.1（ADR-022） |
> |---|---|---|
> | DB | 无（"文件系统即数据库"） | 接入共享 PostgreSQL 的 `research` schema（结构化状态投影；叙事仍以 vault markdown 为事实源） |

## 1. 产品概述

### 1.1 一句话定位

把"研究一只股票 8 小时"变成"审读一份可信报告 1 小时"的 AI 研究助手——且第二次研究同一只票时，agent 带着上次的记忆。

### 1.2 解决的痛点

| 痛点 | 现状 | EquityDeep 解法 |
|---|---|---|
| 数字不可信 | LLM 直接回答财务问题会幻觉（编造市盈率、记错营收） | 所有数字强制来自工具返回，报告逐数溯源 |
| 研究不复利 | 每次研究从零开始，上次的结论、疑点全部丢失 | 个股档案持久沉淀，越用越懂这只票 |
| 覆盖不过来 | 自选池 20 只票，人工只能深挖 3-5 只 | 一次任务自动执行全流程，边际成本近零 |

### 1.3 三个硬承诺（产品的全部价值）

1. **数字可信**：报告里每个数字都能点到原始数据文件
2. **研究复利**：上次结论、疑点、被推翻的判断都沉淀，下次带着用
3. **观点分层**：事实（有引用）、推断（有依据）、存疑（进疑点清单）明确标注

## 2. 用户与场景

### 2.1 目标用户（v1 只有一类）

**自用型个人研究者**：
- 有一定投研基础，看得懂 ROE 和 DCF
- 自选池 10~50 只股票
- Python 环境可自建，Obsidian 重度用户
- 时间有限，需要高效研究工具

### 2.2 核心用户故事

**US-1 首次深度研究**
> 输入"600519"，Agent 在 8 分钟内产出包含商业模式、财务质量、估值、风险、同业对比的深度报告，每个数字都能点开看到来源。

**US-2 第二次研究（复利核心场景）**
> 三个月后再 research 600519，agent 读档案发现上次有疑点"存货周转异常"，本次自动将其列为专项验证项，报告含"疑点追踪"章节。

**US-3 追问与延续**
> 报告看完后在 CLI 直接问"合同负债为什么涨"，agent 基于当前研究上下文继续深挖，不重跑全流程。

**US-4 导入研报**
> 把券商研报 PDF 丢进 `vault/inbox/`，agent 解析出观点和供应链关系存入档案（用户自己的资料，完全合规）。

## 3. 功能需求

优先级：**P0** = MVP 必须；**P1** = 第二迭代；**P2** = 远期。

### 3.1 P0 功能全集

| ID | 功能 | 说明 | 验收标准 |
|---|---|---|---|
| F1 | 固定流程深度研究 | 六章节：公司画像/财务分析/估值/同业对比/风险/结论摘要 | 10 只金标准票事实错误≤1处/份 |
| F2 | 数字溯源 | 每个数字脚注指向 `content_hash`（内容坐标），经 `GET /api/evidence/{content_hash}` 取回唯一原始记录，含 as_of | 回查覆盖率 100%（无来源数字=0） |
| F3 | 研究档案 | Obsidian markdown，显式增量更新 | 二轮研究报告引用上轮结论≥3处 |
| F4 | 疑点跟踪 | 未解决问题进档案，下轮强制验证 | 疑点被新数据解决时状态可翻转 |
| F5 | 追问 | CLI 交互，共享上下文，触发增量取数 | 追问不产生无来源数字 |
| F6 | 评估回归 | 10 只金标准票 + 自动评分脚本 | 改 prompt 必须先跑回归 |
| F7 | 研报 PDF 解析 | inbox/ 目录导入，抽取观点+关系进档案 | 10 份 PDF 测试抽取准确 |

### 3.2 P1 / P2

- **P1**：批量精简报告、双源交叉校验、公告半自动获取
- **P2**：产业链图谱、宏观关联、美股

## 4. 报告质量规范

1. **数字零幻觉**：LLM 生成阶段只允许引用数据摘要中出现的数字；渲染后跑回查脚本，每个数字（含单位换算）必须能按 `content_hash` + JSON Pointer 精确命中 `ingest.raw` 中的原始记录，否则重写（最多 1 次），仍失败显示 `[数据待核]` 而非编造
2. **时效标注**：所有指标带报告期（如 2025Q3）和证据时间（`ingest.raw.as_of`/`fetched_at`）
3. **三层标注**：正文区分【事实】/【推断·依据】/【存疑→档案】
4. **风险章节必须真实检索**：负面新闻、监管处罚、减持公告定向检索，不回避

## 5. 非功能需求

| 类别 | 需求 |
|---|---|
| 运行环境 | Python 3.11+；可本机运行，也可作为 `equitydeep-research` worker 容器接入共享平台（ADR-022） |
| 性能 | 单票完整研究≤8分钟；追问≤60秒 |
| 成本 | 单票≤¥5（模型分级+固定调用次数） |
| 可靠性 | 数据源失败自动降级备源；平台不可达时降级为只读研究（`equitydeep evidence --cache` 离线核验路径） |
| 安全 | 叙事与结构化状态本地/平台内留存，不上传第三方 |
| 可审计 | 每次研究留完整 log（LLM 调用、工具返回） |
| 数据主权 | 叙事事实源 = Obsidian vault markdown；结构化状态 = 共享 PG `research.*` 投影（可 DROP 重建）；原始数字证据 = PG `ingest.raw`（`content_hash` 锚定） |

## 6. 里程碑（12 周）

| 里程碑 | 时间 | 交付 | 硬验收 |
|---|---|---|---|
| **M1** | W1-2 | 数据层：L0 只读证据 API 取数 + 原始响应归档 `ingest.raw` + 质量抽检报告 | 10 票×20 数字错误率<2%，否则换源重做 |
| **M2** | W3-4 | 计算层+LLM 综合+回查脚本 | 金标准 10 票达标：错误≤1处/份，溯源 100% |
| **M3** | W5-6 | 档案读写+疑点机制+复用验证 | 二轮引用上轮结论≥3处 |
| **M4** | W7-8 | 追问循环+PDF 解析导入 | F5/F7 验收通过 |
| **M5** | W9-12 | 打磨+缓冲 | 自用日常化 |

**M1 是全项目硬门槛：数据不可信，后面一切作废。**

## 7. 非目标（MVP 明确不做）

- ❌ 产业链图谱、供应链占比推断 → P2（档案 schema 预留字段）
- ❌ 宏观关联、政策映射 → P2
- ❌ 实时监控/告警、批量自选池 → P1 后段
- ❌ 交易建议、目标价（永久红线）
- ❌ Web UI、多用户（CLI + Obsidian 足够）
- ❌ 美股（A股先跑通，数据层同一套接口）

---

## 8. 合规红线

- 报告显著位置标注："本内容为研究辅助工具产出，不构成任何投资建议"
- 不接入、不存储用户实盘账户信息
- 不自动爬取券商研报（用户自行导入）

## 9. 成功指标

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 事实准确率 | ≥98%（错误≤1处/份） | 金标准集人工抽检 |
| 覆盖度 | 命中金标准要点≥85% | 评估集自动比对 |
| 幻觉率 | 报告中无法溯源数字=0 | 数字回查脚本 |
| 复利验证 | 二轮引用上轮结论≥3处 | 人工检查 |
| 效率 | 8h/股 → 1h 审读+修正/股 | 自计时 |

## 附录：核心数据字段定义

### 财务数据字段（原 akshare 接口 → ADR-022 起经 L0 只读证据 API）

> **ADR-022**：EquityDeep 不再自行调用 akshare。下列字段由底座 L0 数据面提供（akshare adapter 归入 L0），EquityDeep 经只读证据 API 取数，原始响应归档于 `ingest.raw`。字段口径归 L0，本节仅声明消费需求。

| 字段 | 说明 | 用于章节 |
|---|---|---|
| 营业总收入 | 报告期累计 | 财务分析/估值 |
| 归母净利润 | 报告期累计 | 财务分析/估值 |
| 毛利率 | (营收-营业成本)/营收 | 财务分析 |
| 合同负债 | 预收款，渠道话语权指标 | 财务分析/疑点 |
| 货币资金 | 现金储备 | 财务分析 |
| 经营现金流 | 现金流质量 | 财务分析 |
| ROE（加权） | 杜邦分解 | 财务分析/同业对比 |
